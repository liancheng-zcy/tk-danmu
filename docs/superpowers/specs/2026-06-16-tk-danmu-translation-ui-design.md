# TK 弹幕翻译 UI 收敛设计

## 目标

本轮仅做一版面向 Windows 首发的桌面工具收敛优化，聚焦两件事：

1. 将翻译服务范围收敛为 `阿里云 MT`、`微软翻译`、`OpenAI 兼容` 三种模式。
2. 将当前偏模板化的主界面重做为更清晰、更耐用、更适合直播监看的桌面工作台，并加入深浅模式切换。

## 范围

### 保留

- 单直播间输入与启动/停止会话
- 源语言自动检测与手动切换
- 目标语言切换
- 礼物显示开关
- 悬浮窗入口
- 本地保存设置

### 收缩

- 删除 `硅基流动` 和 `GLM-4-Flash` 两个预设模式
- 默认主测路径改为阿里云 MT，减少用户首次配置负担

## 界面方向

采用“专业播控台”方向，而不是泛玻璃卡片风：

- 左栏负责控制与配置，右栏负责实时消息流
- 顶部使用清晰标题、状态信息和主题切换，而不是堆砌渐变卡片
- 主界面统一名称为 `TK 弹幕翻译`
- 深色与浅色主题同时设计，保证两套主题都可直接使用

## 交互与信息层级

### 控制区

- 直播间、代理、翻译服务、源语言、目标语言保持主流程顺序
- 翻译服务配置区只展示当前服务所需字段
- 明确标注哪些字段必填
- 增加服务说明：
  - 阿里云：推荐优先测试
  - 微软：需要用户自己创建 Azure Translator 资源，免费层可用但仍需 `API Key + Region`
  - OpenAI 兼容：需要 `API Key + Base URL + Model`
- 未配置翻译时，明确提示“将只展示原文，不会调用翻译服务”

### 消息区

- 弹幕、礼物、状态消息使用不同视觉样式
- 弹幕卡片优先展示译文，并保留状态信息
- 双语模式下同时展示原文和译文
- 礼物消息只展示，不参与翻译

## 数据与配置变更

- `TranslatorProviderId` 收敛为三种：
  - `aliyun-mt`
  - `microsoft-translator`
  - `openai-compatible`
- `AppSettings` 新增主题字段，用于本地持久化深浅模式
- 默认翻译服务改为 `aliyun-mt`
- 旧设置归一化时，若读到已移除的 provider，则回落到默认 provider

## 用户可见文案

- 清理现有乱码中文文案，统一为 UTF-8 中文
- 统一窗口标题、页签标题、悬浮窗标题与页面主标题

## 验证

- 前端测试覆盖：
  - provider 收敛后的配置切换
  - 深浅模式开关
  - 消息区礼物开关与双语展示
- 运行验证：
  - `npm test`
  - `npm run build`
  - `npm run tauri dev`
